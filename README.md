# Сайт автоэлектрика Берика

Статический двуязычный сайт частного автоэлектрика в Караганде. Русская версия размещена в корне, казахская — в `/kk/`. Проект построен на Astro SSG без клиентского фреймворка и лишнего JavaScript.

## Технологии

- Astro 7 и TypeScript в строгом режиме;
- официальный `@astrojs/sitemap`;
- обычный CSS, семантический HTML и progressive enhancement;
- GitHub Pages и официальный GitHub Action Astro.

Требуется Node.js 24 (минимально поддерживаемая проектом версия — 22.23.4) и npm.

## Локальный запуск

```bash
npm install
npm run dev
```

Проверка типов и production-сборка:

```bash
npm run check
npm run build
npm run preview
```

Готовый статический сайт создаётся в `dist/`.

## Структура

- `src/data/business.ts` — телефон, WhatsApp, точка карты, зона работы и OLX;
- `src/data/services.ts` — русские и казахские карточки услуг;
- `src/data/servicePages.ts` — тексты отдельных страниц услуг;
- `src/i18n.ts` — маршруты и общие переводы интерфейса;
- `src/layouts/` — общие шаблоны главной, услуги, контактов и privacy;
- `src/pages/` — маршруты SSG;
- `src/styles/global.css` — дизайн-система и адаптивная вёрстка;
- `.github/workflows/deploy.yml` — автоматический деплой.

## GitHub Pages

Workflow запускается при push в `main`. По умолчанию `astro.config.mjs` вычисляет адрес и `base` из переменной GitHub `GITHUB_REPOSITORY`, поэтому project page вида `https://user.github.io/repository/` работает без ручной правки ссылок.

1. Создайте GitHub-репозиторий и отправьте код в ветку `main`.
2. В **Settings → Pages → Build and deployment** выберите **GitHub Actions**.
3. После успешного workflow проверьте URL, canonical, `robots.txt` и sitemap.

Для нестандартного адреса GitHub Pages можно задать repository variables:

- `SITE_URL` — origin без завершающего слеша, например `https://user.github.io`;
- `BASE_PATH` — базовый путь, например `/berik`.

## Собственный домен

1. Настройте DNS у регистратора и GitHub Pages по документации GitHub.
2. Добавьте `public/CNAME`, содержащий только подтверждённый домен.
3. Создайте repository variable `SITE_URL` со значением `https://ваш-домен.kz`.
4. Оставьте `BASE_PATH` пустым или задайте `/`.
5. Включите **Enforce HTTPS** в настройках Pages.

## Контент и контакты

Главные сведения редактируются в `src/data/business.ts`. Телефон хранится в международном формате отдельно от отображаемого варианта. WhatsApp-ссылка и готовый текст формируются автоматически.

Чтобы добавить или изменить услугу, обновите обе языковые коллекции в `src/data/services.ts`. Для новой полноценной страницы добавьте тексты в `src/data/servicePages.ts` и пару маршрутов в `src/i18n.ts`.

## Фотографии

Первая версия не выдаёт стоковые или сгенерированные изображения за реальные работы. Когда появятся разрешённые оригиналы:

1. сохраните оптимизированные `.webp`/`.avif` в `src/assets/`;
2. удалите из кадров номера, VIN и другие персональные данные;
3. используйте компонент Astro `<Image />` с точными `width`, `height` и содержательным `alt`;
4. добавляйте подпись кейса только после подтверждения марки, симптома и выполненной работы.

## Аналитика

GA4 и Яндекс Метрика не подключены. В разметке уже подготовлены события:

- `click_phone`;
- `click_whatsapp`;
- `click_directions`;
- `click_service`;
- `click_olx_contact`.

После получения идентификаторов добавьте официальные компактные сниппеты в `BaseLayout.astro`, обновите страницу обработки данных и настройте consent-механику, если она требуется применимыми правилами.

## SEO-чеклист перед запуском

- подтвердить фактический production URL и проверить canonical/hreflang;
- открыть `sitemap-index.xml` и `robots.txt` по публичному адресу;
- добавить сайт в Google Search Console и Яндекс Вебмастер;
- проверить русские и казахские страницы, 404 и внутренние ссылки;
- проверить данные Schema.org валидатором;
- подтвердить название и адрес в картах и локальных справочниках;
- добавить разрешённые реальные фотографии и содержательные подписи;
- прогнать Lighthouse на мобильном и десктопе;
- проверить звонок, WhatsApp и маршрут на реальном телефоне.

## Что нужно подтвердить до публикации

- точный почтовый адрес и способ въезда в мастерскую;
- рабочие часы и дни;
- условия заявленной в OLX пожизненной гарантии на соединения проводки;
- точную зону, стоимость и условия выезда;
- цены или правила расчёта стоимости;
- права на публикацию фотографий работ;
- идентификаторы аналитики, если она нужна;
- GitHub-репозиторий и/или собственный домен.

На сайте эти сведения не выдумываются: вместо них используются честные пояснения «уточните при обращении».
